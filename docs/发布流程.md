# 知止 Stoic 发布流程

适用：独立分发（不上架 App Store）

## 一、版本号

- 唯一来源：仓库根 `VERSION`（`x.y.z`，各位数 0–9，`z` 满 9 进位）。
- 构建号：打包时取 `YYYYMMDDhhmmss`，由 `scripts/build-app.sh` 写入 `CFBundleVersion`。

## 二、每次发布

1. 改 `VERSION`。
2. `./scripts/smoke.sh`（构建 + 53 个测试 + 启动检查）。
3. `./scripts/make-dmg.sh` 生成 `dist/Stoic-<版本>.dmg`。
4. 有证书时：`DEVELOPER_ID="Developer ID Application: …" NOTARY_PROFILE=xxx ./scripts/make-dmg.sh`。
5. 上传 DMG 到自己的下载地址，更新更新清单 JSON（`version` / `url` / `notes`）。
6. 把应用设置里的「更新清单地址」填成该 JSON 的 URL。

## 三、灰度

| 阶段 | 人数 | 时长 | 通过条件 |
|---|---|---|---|
| 内部 | 自己 | 3 天 | 无崩溃；计时与记录无异常 |
| 小范围 | 3–5 人 | 1 周 | 无 P0；反馈可归类 |
| 全量 | 全部 | — | 小范围无回滚 |

回滚：把更新清单的 `version` 改回旧版，保留旧 DMG 链接；不覆盖旧文件。

## 四、崩溃诊断

- 应用把 MetricKit 诊断写到 `~/Library/Application Support/StoicLogs/`。
- 符号化：`./scripts/symbolicate.sh <diagnostics-*.json> build/Stoic.app`（需要未剥离的可执行文件或 dSYM）。
- 不上传、不自动收集；需要用户主动提供文件。

## 五、发布检查清单

- [ ] `VERSION` 已更新，构建号自动生成
- [ ] `./scripts/smoke.sh` 通过
- [ ] DMG 可挂载、`Stoic.app` 可启动
- [ ] 更新清单 JSON 已更新
- [ ] 隐私政策与实际行为一致
